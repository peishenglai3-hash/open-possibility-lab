# Project origin and name

## The problem behind the code

This project did not begin with a model or a framework. It began with a practical failure of
research collaboration: a team can produce a large amount of material and still lose the conditions
under which that material could be understood, contested, revised, or used.

Four failures were treated as design problems:

1. **Directional isolation.** Local inquiries do not meet; the team accumulates observations but
   not a shared orientation.
2. **Temporal mismatch.** The object of study changes faster than the team's questions; old framing
   survives as unexamined common sense.
3. **Information without interpretation.** Records preserve statements but lose situation, scope,
   disagreement, and the reason a decision was closed.
4. **Concentrated strategic cognition.** A few people hold the whole; most hold fragments; the
   asymmetry becomes a product rather than a problem.

The project's answer is not to build a smarter team mind. It is to build external conditions:
append-only history, rebuildable projections, protected dissent, scoped and reopenable closure,
binding provenance, and a real exit.

## Three contractions

The project has repeatedly reduced its own claims. These reductions are part of the design, not
embarrassing leftovers.

### 1. From "team soul" to a scoped projection

The early material used ambitious language about a team-level soul, collective cognition, or a
system that understands a team better over time. Engineering did not accept those as existing
objects.

The runtime instead implements:

- a derived, scoped, time-bounded TeamView, not a second truth;
- operational closure, not final consensus;
- explicit uncertainty and missing evidence;
- no claim of consciousness, subjectivity, or a stable collective identity.

### 2. From "better reasoning" to testable structural properties

The project asked whether external organization of history, problems, relations, transfer
constraints, and revocable closure can improve the stability of a model's work under a fair budget.
It also wrote its own exit condition: if a simpler baseline or ordinary retrieval does the same
job, the project should be downgraded.

The experiments did not produce a general reasoning advantage. That negative result is retained.

### 3. From "build a system" to "make the interaction non-coercive"

Week 03 moved the question to the interaction layer:

- Can a person get direct help without being forced through an exploration ritual?
- Can sources, dissent, alternatives and missing evidence be available without being demanded?
- Can a person change direction, refuse, or stop without justification or follow-up?
- Can the result leave the system and remain readable?

The answer is a small synthetic slice, not a product. It passes structural and browser checks; it
does not establish user benefit.

## The north star

The Chinese line is:

> 让可能性自由进入现实，也允许现实不按照期待发展。

In English:

> Let possibility enter reality freely; and let reality refuse the expectation.

This is a claim about **conditions**, not about outcomes. A system that only permits the expected
future is not open, even if it offers many options. A system that forces every option to be
explored is also not open, because it makes refusal expensive.

## Why the name Open Possibility Lab

The name has three parts:

- **Open**: the conditions must remain contestable and exitable; openness is not a feature count.
- **Possibility**: the object is the space of actions and interpretations that can enter, not a
  predicted user journey.
- **Lab**: this is a research prototype with explicit evidence levels, failures, and an exit
  condition, not a product brand.

The Python package keeps the historical name team_soul because the frozen runtime and tests use it.
That is continuity, not a metaphysical claim. The public repository name is new.

## What this project refuses

- A team-level subject, collective consciousness, or "the team's soul".
- A claim that more openness automatically improves judgement, trust, or learning.
- A claim that engagement, retention, or adoption are evidence of value.
- Turning refusal, attention, or non-use into a profile or performance metric.
- A production governance system built on a research prototype.
