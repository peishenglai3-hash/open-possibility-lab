# 开放可能性实验室（Open Possibility Lab）

**一个以来源为先的研究协作工作台。** 保留原始历史，保存异议，让收束可以被重新打开，也让使用者可以拒绝、离开、把成果带走。

**状态：** 研究原型 · 仅合成证据 · E1 结构性证据 · 不宣称生产可用或用户收益。

---

## 缘起

大多数 AI 协作工具围绕“下一个答案”组织：总结会议、排序文档、生成方案、留住用户。它们有用，但也在悄悄决定什么才算问题。

这个项目来自另一种观察：研究团队失去的往往不只是信息，而是信息成为解释的条件。

1. **方向孤岛**：不同探究产生局部结果，彼此不相遇；团队有很多观察，却没有共同方向。
2. **时间错位**：社会现象变化快于团队修订问题的速度，昨天的框架悄悄变成今天的答案。
3. **保存了信息，丢失了解释**：记录可以很完整，却无法被后来的人理解，因为情境、范围、分歧和收束理由消失了。
4. **战略认知集中**：少数人持有整体图景，多数人持有碎片，系统把这种不对称变成产品。

这里要做的不是更聪明的助手，也不是团队级心灵，而是为开放探究搭一些**外部条件**：历史不能被悄悄改写；投影永远是派生的、可重建的；异议不被平均掉；收束是暂时的、可重开的；退出是真实的。

> 让可能性自由进入现实，也允许现实不按照期待发展。

## 现在有什么

### 1. 核心 Runtime（src/team_soul）

一个模型中立的、来源先行的研究记录运行时：

- 追加式原始事件是唯一事实源；
- 投影可丢弃、可重建；
- 证据带有范围与不确定性；
- 异议是一等位置，不是噪声；
- 收束有范围、条件与重开条件；
- 模型建议不能直接改写权威状态。

### 2. 开放工作台切片（examples/open-workspace）

一个可以真实运行的小交互，用来检验四种体验能否共存，而不是把“开放”变成仪式：

| 体验 | 做什么 |
|---|---|
| 直接帮助 | 一个动作返回确定性本地回答，带引用与状态标签。 |
| 自主展开 | 来源、异议、替代、缺失、修订、未授信文本、被排除项，只在用户要求时出现。 |
| 改变 / 拒绝 / 停止 | 换问题、完全拒绝当前问题、停止；不需要理由，不追问，不记录拒绝。 |
| 带走成果 | Markdown / JSON 导出，带哈希与限制说明，无本机路径；离开系统也能读。 |

切片是合成的、确定性的。它不是模型产品、不是聊天机器人 benchmark，也不宣称开放会改善人。

## 设计承诺

1. **历史先于摘要。** 摘要可以帮助导航，但不能替代记录成为真相。
2. **投影是派生的。** 任何“团队视图”都是有范围、有时间、可重建的视图，不是第二事实源。
3. **异议不是噪声。** 少数位置被保护，不被压缩成平均意见。
4. **收束为了行动，不是为了永恒。** 收束带范围、证据、不确定性与重开条件。
5. **来源必须绑定决策。** 只作装饰的 source 字段不是 provenance。
6. **相似不等于可迁移。** 邻近案例不是适用案例。
7. **拒绝是合法输出。** 停止、离开、“我不想要”不是要被优化掉的失败状态。
8. **退出是可携带的。** 系统消失后，成果仍然可读。
9. **不搞后门画像。** 注意力、拒绝、不采用，不应变成绩效记录。
10. **不要把研究原型做成治理基础设施。** 项目自带退出条件：如果更简单的基线能做同样的事，就应该降格。

## 当前证据

| 项目 | 结果 |
|---|---|
| 核心测试 | 公开快照 164 passed / 7 skipped；私有上游 226 passed / 3 skipped。差异来自未分发的授权数据与报告。 |
| 切片测试 | 14 passed（composer、export、authority firewall、launcher、AppTest、错误态、强制模式负对照） |
| 真实浏览器走查 | Chrome + Playwright：下载与外部解析、展开后答案稳定、未授信文本按文本显示、Stop 终态、reload 清空；0 console error |
| 独立复核 | 43/43 浏览器检查；核心与切片测试由独立审查者复跑 |
| G3 对照 | 3 任务 × 3 模式；可选开放没有正确性收益；未使用时没有额外负担；强制模式增加 8 次点击 / 7 个面板，答案不变 |
| 证据等级 | 仅 E1 结构性证据：合成任务、一个确定性 responder |

**不成立：** 用户收益、认知提升、信任、Taste、采用、留存、生产力、模型优越性、团队级实体、强 RSI、E2/E4 效应。本仓库没有用户研究，也没有外部产品 baseline。

## 快速开始

需要 Python 3.12。

    git clone https://github.com/peishenglai3-hash/open-possibility-lab.git
    cd open-possibility-lab
    python -m venv .venv
    .venv/Scripts/activate        # Windows
    # source .venv/bin/activate   # Linux / macOS
    pip install -e ".[dev]"
    pytest -q

预期：公开 clone 为 164 passed / 7 skipped；私有上游为 226 passed / 3 skipped。差异来自未分发的授权数据与报告，见 docs/PROVENANCE.md。skip 是环境边界，不是通过。

### 运行开放工作台

    cd examples/open-workspace
    PYTHONPATH=.
    python -m w03.run

打开 http://127.0.0.1:8503。启动器只绑定 loopback，关闭 usage stats，使用 typed error 与最小工具栏；GUI 不 import 权威模块。

### 运行切片测试与 CLI replay

    cd examples/open-workspace
    PYTHONPATH=.
    python -m pytest tests -q
    python cli-replay/replay.py --task T1 --format md

## 研究简史

### Week 01 — 基线

确定性的结构基线：原始历史、投影重建、范围检索、受控迁移、收束与重开。没有真实团队数据。问题是：历史与证据的外部组织能否被测试。

### Week 02 — E1 结构实验

在合成案例上做预注册对照，并加入输入信任与隐私补丁。结果是**混合/负面的**：结构运行时没有表现出一般推理优势；项目自己的退出条件被保留。已知缺陷仍在，见 docs/RESEARCH_STATUS.md。

### Week 03 — 开放交互切片

问题从“这个 runtime 能否赢 benchmark”转向“这些条件能否在交互中不被强制”。切片实现了四种体验，并做了真实浏览器检查。G3 在三个固定任务上得到**零正确性效应**：可选展开没有改善答案，未使用时没有额外负担，强制展开增加成本但不改善答案。这是一个有用的负面结果，不是成功故事。

完整研究记录（包括失败和未完成项）见 docs/RESEARCH_STATUS.md。

## 已知限制

- 仅合成；没有真实团队、真实用户、私有语料或外部知识库。
- 确定性 responder；切片不调用语言模型。
- 3 任务 G3 是结构对照，不是用户研究；oracle 与 composer 同源，只能说明设计一致性，不能说明独立正确性。
- 历史追加式是构造约束，不是防篡改/抗恶意进程的安全声明。GATE-1/T2 与 Week02 D1/D2 仍未解决。
- 本仓库不阻塞 OS 级出网；应用没有网络路径、测试不调用 provider，但这不等于主机无网络。
- 没有 CJK 检索 benchmark、没有 source revocation 生命周期、没有可访问性审计、没有 lockfile。
- 没有生产部署、发布或安全认证。

完整列表见 docs/LIMITS_AND_SECURITY.md。
